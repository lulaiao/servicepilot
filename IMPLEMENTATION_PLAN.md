# ServicePilot implementation plan

Each phase is gated. A phase starts only after the previous acceptance criteria
pass. Metrics are `TBD` until generated by a committed configuration and data
manifest.

Every material framework, storage engine, retrieval component, inference model,
and training framework is governed by `docs/adr/0002-selection-governance.md`.
A candidate becomes selected only after a reproducible comparison against the
simplest baseline and credible alternatives.

## Phase 0 — environment and skeleton

Status: **complete**

- Audit host, permissions, GPU/CUDA, Python, Docker, memory, and disk.
- Record core-stack decision and infrastructure blockers.
- Create repository boundaries, configuration placeholders, and a
  dependency-free smoke test.
- Acceptance: `make smoke` passes.

## Phase 1 — deterministic business simulator

Status: pending

1. Define enums and typed records for orders, payments, refunds, coupons,
   merchant/delivery state, policy version, and audit events.
2. Define legal order/refund state transitions and deterministic policy
   assertions with evidence IDs and effective times.
3. Add repository protocols plus thread-safe in-memory adapters.
4. Implement synthetic fixtures and deterministic seeded generation.
5. Add write services using idempotency records and optimistic version checks.
6. Test every legal/illegal transition, repeated refund key, stale version,
   amount bounds, cancellation/refund exclusions, and coupon restoration.

Acceptance:

- Core rules pass unit tests without Docker, network, or model dependencies.
- Reusing an idempotency key returns the original result and creates no second
  refund.
- A stale expected version cannot mutate an order.
- Final state and policy applicability are independently assertable.

## Phase 2 — MCP and reliability

Status: pending. Add typed Order, Refund, Coupon, Policy, and
Merchant/Delivery servers and a gateway with timeout, retry, typed errors,
audit, confirmation, version checks, and at least five deterministic faults.
Before implementation, verify the current official MCP Python SDK documentation,
pin the tested revision, and record the SDK-versus-minimal-adapter spike.

## Phase 3 — single-agent executable baseline

Status: pending. Implement the FSM user simulator, rule/MockModel policy,
unified traces, budgets, 30+ scenarios, final-state judge, and false-success
detection.

## Phase 4 — intent and dynamic multi-agent routing

Status: pending. Compare rule and local structured-output baselines; route from
full dialogue/tool state on every turn and material tool result.
Select any local model using `docs/model_selection_protocol.md`; report quality,
schema-validity, latency, and memory together.

## Phase 5 — layered memory

Status: pending. Add recent-window, typed working, factual summary, and
consented long-term memory with conflict, expiry, deletion, and privacy tests.

## Phase 6 — hybrid retrieval and evidence verification

Status: pending. Build gold-evidence datasets before BM25+dense retrieval,
metadata filters, query expansion, reranking, context completion, and evidence
sufficiency checks.
Freeze the corpus and compare lexical-only, dense-only, hybrid, and reranked
variants under the same latency and retrieval budget before accepting components.

## Phase 7 — monitors, recovery, and full evaluation

Status: pending. Calibrate bounded deterministic/quality monitors, cover at
least ten fault classes, and scale to at least 1,000 executable trajectories.

## Phase 8 — trajectory data loop

Status: pending. Add redaction, deduplication, leakage-resistant splits,
manifests, hard-negative mining, and reproducible SFT/preference exports.

## Phase 9 — SFT and GRPO

Status: pending and blocked on GPU re-audit. Run small-model LoRA SFT, outcome
GRPO, process-reward experiments, reward-hacking audits, and repeated trials.
Training model/framework choices require a new ADR backed by measured fit,
throughput, peak VRAM, disk, stability, license, and downstream task quality.

## Phase 10 — open-source delivery

Status: pending. Validate a clean-environment quick start, demo, trace viewer,
reports, ablations, and evidence-linked resume statements.
